# Implementation Plan

各タスクはテストを先に書き、落ちることを確かめてから実装する。完了の根拠は Stop フック（EditMode）の終了コードと Test Runner の結果だけとする（tech.md 禁止事項 5）。
タスク 2 以降はすべて群れ（MosquitoSwarm）とそのテストクラスを触るため、並行実行（P）は付けない。タスク 1 も、2 以降が設定値を使うので先に終える。

テストの決まり（design.md「Testing Strategy」）:
- 顔の位置には原点以外（例 (0.5, 1.2, -0.3)）も使い、顔の位置を差し引き忘れる誤りを検出する
- 刺された判定を確かめるテスト以外は、**刺さない設定値**（仮の初期値のうち刺された判定の秒数だけ 1000 秒にしたもの）を使う。タスク 4 で刺された判定が入っても、出現・接近・撃墜のテストの結果が変わらないようにするため
- 時間を細かく刻むときは 1/64 秒（float で誤差なく表せる）を使う

- [x] 1. 設定値を検証して持てるようにする
  - 刺された判定の距離と秒数、出現範囲（水平距離の内側・外側、高さの下限・上限）、同時数の上限、出現間隔、接近の速さの9つを受け取り、生成後は変えられない値として読み出せる
  - 既定値は持たない。内側 = 外側の水平距離、下限 = 上限の高さも受け付ける
  - 不正な値は、design.md「Error Categories and Responses」の例外と引数名で、引数の並び順に検査して知らせる。NaN・無限大も拒否する
  - 完了条件: 次のテストが EditMode で通る
    - 仮の初期値と、それ以外の組（0.1m、0.5秒、0〜0m、0〜0m、1匹、0.1秒、3m/s）で作れて、9つの値が読み出せる
    - 刺された判定の距離・秒数、出現間隔、接近の速さが 0 / -1 / NaN のとき、それぞれの引数名で拒否される
    - 内側 -0.1、外側 < 内側、下限 > 上限、出現範囲の4つの値それぞれの NaN、同時数 0 / -1 で、決められた引数名（`spawnMinHeight` を含む）で拒否される
  - _Requirements: 9.1, 9.2, 9.3, 9.4, 10.5_

- [x] 2. 蚊を出現させられるようにする
- [x] 2.1 群れの開始・停止と、経過秒数の検証を用意する
  - 群れのテストが使う型をすべて用意する：乱数のインターフェース、蚊の状態の列挙、蚊（識別子・位置・状態・累積秒数を読み出せるだけ）、時間経過の結果（出現した蚊・刺した蚊の一覧。この時点では常に空）
  - テスト用に、決めた値を順に返す乱数を用意する（テストのアセンブリに置く）。群れのテストの共通の準備（仮の初期値の設定値、刺さない設定値、群れを作る補助）もここで作る
  - 群れは設定値と乱数を受け取って作る。どちらかが無いときは引数名つきで拒否する
  - 作った直後は出現していない。開始すると出現中になり、停止すると出現中でなくなる。停止中の停止は何もしない
  - 経過秒数が負・NaN・無限大のときは、決められた例外と引数名で拒否し、何も変えない
  - 出現中でないときに時間を進めても、何も起きず空の結果が返る
  - 完了条件: 「作った直後は出現中でなく、5秒進めても蚊がいない」「開始・停止で出現中の状態が切り替わる」「負・NaN・無限大の経過秒数が拒否される」「設定値・乱数が無いと拒否される」テストが EditMode で通る
  - _Requirements: 1.1, 9.5_

- [x] 2.2 出現の位置と、最初の1匹を決める
  - 開始したあと最初に時間を進めたとき（経過秒数 0 を含む）に1匹だけ出す。このタスクでは「開始後の最初の時間経過かどうか」だけで決め、出現間隔と同時数はタスク 2.3 で入れる
  - 出現位置は、そのときの顔の位置を基準に、乱数を3回引いて決める：角度 θ = 2π·u1、水平距離 r = 内側 + (外側 − 内側)·u2、高さの差 h = 下限 + (上限 − 下限)·u3、位置 = 顔 + (r·cos θ, h, r·sin θ)。Y 軸を上とする
  - 乱数が [0, 1) の外や NaN を返しても、[0, 1] に切り詰めて出現範囲を守る（NaN は 0）
  - 蚊は識別子・位置・状態（接近中）を読み出せる。識別子は 1 から出現のたびに増え、開始し直しても戻さない
  - 時間経過の結果で、その時間経過で新たに出現した蚊を読み出せる
  - 停止すると蚊はすべて取り除かれ、その後時間を進めても出ない。開始し直すと前回の蚊を引き継がない
  - 複数の蚊の位置を確かめるテストは、「開始 → 経過秒数 0 で進める」を繰り返して1匹ずつ出す
  - 完了条件: 次のテストが EditMode で通る
    - 乱数 (0,0,0) → 顔 + (1.0, -0.5, 0)、(0.25,1,1) → 顔 + (0, 0.5, 2.0)（許容誤差つき）
    - 範囲外・NaN の乱数でも範囲内、100回出してすべて範囲内
    - 同じ乱数の並びなら、2つの群れで同じ位置が同じ順に出る
    - 停止で空になり、以後出ない。開始し直すと1匹だけ出て、識別子は前の蚊と重ならない
  - _Requirements: 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 8.1, 8.2, 8.4, 10.3_

- [x] 2.3 出現間隔と同時数の上限を守る
  - 直前の出現からの経過秒数を持つ。開始時は出現間隔と同じ値にする（タスク 2.2 の「最初の時間経過かどうか」をこれに置き換える）
  - 時間経過のたびに経過秒数を足し、それが出現間隔以上で接近中の数が上限未満の間、1匹出して出現間隔を引く
  - 完了条件: 刺さない設定値で、次のテストが EditMode で通る（タスク 2.2 の実装では 1/64 秒刻みの2匹目と、5秒で3匹が出ないので落ちる）
    - 1/64 秒ずつ進めると、t = 0、2.0、4.0 秒で出て、4匹目は出ない。各時間経過の結果には、その時間経過で出た蚊だけが入る
    - 開始直後に 5 秒進めると3匹、100 秒進めても3匹
    - 3匹いる状態で停止すると一覧が空になり、以後時間を進めても出ない
  - _Requirements: 1.3, 3.1, 3.2, 3.4, 8.2_

- [x] 3. 蚊を顔へ近づけ、撃墜できるようにする
- [x] 3.1 顔へ近づける
  - 時間を進めるたび、接近中の各蚊を、その時点の顔の位置へまっすぐ「接近の速さ×経過秒数」だけ動かす。顔の位置を通り過ぎるなら顔の位置で止める
  - 1回の時間経過の中では、既存の蚊を動かしてから出現を判定する。出現したばかりの蚊はその時間経過では動かない
  - 家具や壁との当たり判定は持たない
  - 完了条件: 刺さない設定値で、次のテストが EditMode で通る
    - 顔から 1.5m の蚊が1秒で 0.5m 近づく、0.2m の蚊が顔の位置で止まる
    - 顔を動かすと新しい顔の位置へ向かう
    - 経過秒数 0 で位置・状態が変わらない、出現した時間経過では出現位置から動かない
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_

- [x] 3.2 命中を受けて撃墜し、空いた枠の出現を整える
  - 接近中の蚊の識別子で命中を知らされたら、撃墜にして一覧から外し、成功と、その蚊を返す。蚊の位置は撃墜した時点のまま変わらない
  - 撃墜済み・存在しない・停止で取り除かれた蚊への命中は、失敗と空を返し、何も変えない
  - 出現のあと上限に達していたら、経過秒数を出現間隔で頭打ちにする（待ち時間を貯めない）。空いた枠は次の時間経過で1匹だけ埋まり、2匹目は出現間隔を待つ
  - 完了条件: 刺さない設定値で、次のテストが EditMode で通る
    - 撃墜すると状態が撃墜になり、位置が変わらず、一覧の数が1減る
    - 撃墜済み・存在しない・停止後の識別子では失敗する
    - 上限3匹で10秒進めてから1匹撃墜すると、次の 1/64 秒で1匹出る。続けて2匹撃墜しても、次の 1/64 秒では出ない（頭打ちがないと2匹出るので、このテストが頭打ちの RED になる）
  - _Requirements: 3.2, 3.3, 3.5, 5.1, 5.3, 5.4, 8.3_

- [x] 4. 刺された判定を入れる
  - 動いたあとの顔との距離が刺された判定の距離以下（許容誤差 1e-5m を含む）なら、その経過秒数を蚊ごとの累積秒数に足す。範囲外では足さず、0 にも戻さない
  - 累積秒数が刺された判定の秒数以上（許容誤差 1e-5 秒を含む）になったら刺した状態にし、一覧から外して、時間経過の結果に入れる
  - 刺す判定は移動のあと、出現の判定の前に行う。刺した蚊は以後動かず、命中の対象にも刺された判定の対象にもならない
  - 蚊を顔の位置に出すときは、出現範囲を水平 0〜0m・高さ 0〜0m にした設定値を使う
  - 完了条件: 次のテストが EditMode で通る
    - 顔の位置で 2.0 秒経つと刺す（結果に入り、状態が刺したになり、その識別子が一覧から外れる。同じ時間経過で空いた枠に次の蚊が出ることがあるので、一覧が空かどうかでは確かめない）。1.99 秒では刺さない。0.1 秒×20回（float の累積誤差が出る刻み）でも刺す
    - 距離ちょうど 0.3m に保つと秒数が足され、0.301m では足されない
    - 範囲を出て戻っても累積が続く（離れている間の累積秒数は変わらない）。片方の蚊の秒数がもう片方に足されない
    - 仮の初期値以外の設定値（0.1m、0.5秒、3m/s）で、刺されるまでの秒数が変わる
    - 出現間隔 0.1 秒で顔の位置に2匹を同時に出し、2.0 秒進めると結果に2匹入る
    - 刺した蚊への命中が失敗する。以後の時間経過の結果に同じ蚊が入らない
    - 撃墜した蚊は、顔の位置で何秒進めても刺さない（実装前から通る回帰の確認）
  - _Requirements: 3.5, 5.2, 6.1, 6.2, 6.3, 6.4, 6.5, 7.1, 7.2, 7.3, 8.2, 10.4, 10.5_

- [x] 5. テストの網羅を点検する
  - design.md「Testing Strategy」の「実行」に挙げた公開メンバーのそれぞれに、少なくとも1本のテストがあることを確認し、無ければ足す
  - 境界4ケース（距離ちょうど・累積秒数ちょうど・顔の位置を通り過ぎる移動・範囲を出入りしたあとの累積）がテストで固定されていることを確認する
  - 完了条件: spray-hit-core のテストを含む全テストが、Stop フック（EditMode、シーンを開かない）で通る
  - _Requirements: 10.1, 10.2, 10.4_

## Implementation Notes
- 2.3: 上限に達している間の経過秒数は、まだ頭打ちにしていない（増え続ける）。頭打ちはタスク 3.2 で MosquitoSwarm の出現ループのあとに足す。1/64 秒刻みのテストが見る出現は、最初の時間経過（t=1/64）・2.0・4.0 秒で、仕様の「t=0」は「開始後の最初の時間経過」を指す
- Unity の Editor を開いたままのとき、テストは `unity command run_tests --mode EditMode --result-only` で走らせる（JSON の Summary.Failed で判定する）。テスト名・メソッド名は数字で始められない
- 3.1: `Mosquito.Approach` は仮の内部 API。タスク 4 で、設計の `Advance(deltaTime, face, rules)`（接近 + 刺された判定、刺したら true）へ拡張・改名する。「距離ちょうど 移動量」のテストは、上限で止める分岐の有無を区別できない（結果が同じ）
- 3.2: 撃墜のテストは MosquitoSwarmTests.Hit.cs に置いた（design.md の File Structure Plan は .Spawn / .Flight / .Bite の3つ。Hit.cs を足した）。`Mosquito.Down()` の状態チェックは TryHit 経由では到達しない防御で、テストでは検出できない
- 4: `Mosquito.Approach` は private に下げ、設計どおりの `Advance(deltaTime, face, rules)`（接近 + 刺された判定）に置き換えた。ちょうど 0.3m のテストは float の誤差で許容誤差の有無を区別できないので、0.300005m のテストが区別を担う
- 5: 点検だけでコードの変更はない。公開メンバー（MosquitoRules の生成と9プロパティ、MosquitoSwarm の生成・Rules・IsSpawning・Mosquitoes・Start・Stop・Advance・TryHit、Mosquito の4プロパティ、AdvanceResult の2プロパティ）のすべてに1本以上のテストがあり、境界4ケースも固定されている。コードの差分がないので、タスク単位のレビューは行わず、最終の `/kiro-validate-impl` に任せた
