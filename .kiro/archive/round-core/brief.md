# Brief: round-core

## Problem
待機・プレイ・結果の流れと、1分の制限時間、スコアの規則がないと、1回の遊びとして閉じない。
定位置から離れたときの警告も、外部設計では必須なのに、人の表のどこにも入っていなかった。

## Current State
コードはない。人の表では game-session-core という名前で、離脱警告を含んでいなかった。

## Desired Outcome
ラウンドの状態遷移（待機 → プレイ → 結果 → 待機）、残り時間、撃墜数、スコアが規則どおりに変わり、EditMode テストで確かめられる。
ラウンド開始時に定位置が記録される。プレイヤーの位置を渡すと、離脱警告を出すべきかが返る。

## Approach
ラウンドの状態機械を Core に置く。時間は経過秒数として外から渡す。
撃墜と刺されはイベント（またはメソッド呼び出し）として受け取り、スコアに反映する。mosquito-core の型は直接参照しない。
離脱判定は、定位置からの距離としきい値で決める純粋な関数として、ラウンドの状態遷移とは独立に置く。

## Scope
- **In**: 状態遷移と開始・再開の条件、制限時間（1分）、撃墜数とスコアの規則（撃墜で加点、刺されで減点）、定位置の記録、離脱判定と解除
- **Out**: トリガー入力の取得、表示、頭の位置の取得

## Boundary Candidates
- ラウンドの状態遷移と時間
- スコアの規則
- 定位置と離脱判定

## Out of Boundary
- 離脱警告中にラウンドを止めること（外部設計では、警告中も残り時間・蚊・噴射は続く）
- スコアの保存・ランキング（対象外）
- 難易度の選択（ラウンドの条件は1種類）

## Upstream / Downstream
- **Upstream**: なし
- **Downstream**: round-flow-adapter（入力・蚊のイベント・頭の位置を渡す）、round-hud-adapter（状態を表示する）

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: mosquito-core（撃墜・刺されのイベントの形を揃える）

## Constraints
- `MosquitoSpray.Core` に置き、UnityEngine を参照しない
- 離脱判定をここに置いたのは、定位置が「ラウンドを始めた位置」と定義されているから。加えて、別 spec にすると round-flow-adapter の依存が3つになるから。ラウンドの状態遷移と混ぜない
- 離脱のしきい値は外部設計の「一歩以上」をもとに requirements で数値にする
