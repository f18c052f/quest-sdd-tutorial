# Requirements Document

依存する spec: なし

## Project Description (Input)
**誰が困っているか**：プレイヤー（と、規則を実装・テストする開発者）。待機・プレイ・結果の流れと、1分の制限時間、スコアの規則がないと、1回の遊びとして閉じない。定位置から離れたときの警告も、外部設計では必須なのに、人の表のどこにも入っていなかった。

**現状**：コードはない。人の表では game-session-core という名前で、離脱警告を含んでいなかった。

**何を変えるか**：ラウンドの状態遷移（待機 → プレイ → 結果 → 待機）、残り時間、撃墜数、スコアが規則どおりに変わり、EditMode テストで確かめられるようにする。ラウンドの状態機械を `MosquitoSpray.Core` に置き、時間は外から経過秒数として渡す。撃墜と刺されはイベント（またはメソッド呼び出し）として受け取ってスコアに反映し、mosquito-core の型は直接参照しない。ラウンド開始時に定位置を記録し、プレイヤーの位置を渡すと離脱警告を出すべきかが返る。離脱判定は、定位置からの距離としきい値で決める純粋な関数として、ラウンドの状態遷移とは独立に置く。

**範囲**
- In：状態遷移と開始・再開の条件、制限時間（1分）、撃墜数とスコアの規則（撃墜で加点、刺されで減点）、定位置の記録、離脱判定と解除
- Out：トリガー入力の取得、表示、頭の位置の取得、離脱警告中にラウンドを止めること（警告中も残り時間・蚊・噴射は続く）、スコアの保存・ランキング、難易度の選択（ラウンドの条件は1種類）

**制約**
- `MosquitoSpray.Core` に置き、UnityEngine を参照しない
- 離脱判定をここに置くのは、定位置が「ラウンドを始めた位置」と定義されているから。加えて、別 spec にすると round-flow-adapter の依存が3つになるから。ラウンドの状態遷移と混ぜない
- 撃墜・刺されのイベントの形は mosquito-core と揃える
- 離脱のしきい値は外部設計の「一歩以上」をもとに requirements で数値にする

## Introduction
1回のラウンドの流れ（待機 → プレイ → 結果 → 待機）、制限時間、撃墜数とスコア、定位置と離脱判定の規則を、ゲーム画面やシミュレータを使わずにテストで確かめられる計算として定める。
時間は呼び出し側が経過秒数として渡し、トリガーが引かれたこと（開始の指示）・撃墜・刺されたこと・プレイヤーの位置も呼び出し側がそのつど渡す。長さはメートル、時間は秒で扱う。

スコアは撃墜で 1 点増え、刺されると 1 点減る。0 点より下にはならない。撃墜数はスコアとは別に数え、刺されても減らない。

離脱判定は、定位置からの**水平距離**だけで決める。座る・立つで頭の高さが変わっても警告しない。
警告を出す距離と消す距離を分け、境目で頭が揺れても警告が点滅しないようにする。
離脱警告はラウンドの進行に影響しない。警告中も残り時間は減り、撃墜と刺されたことはスコアに反映される。

結果に入ってからしばらくは開始の指示を受け付けない。制限時間の瞬間に噴射していたプレイヤーが、結果を見ないまま待機へ戻ってしまうのを防ぐためである。

数値は次のとおりに置く。点数の規則は固定する。それ以外は**仮の初期値**であり、シミュレータで確かめながら調整する前提で、規則はどの正しい値に対しても成り立つようにする。
値を調整したときは、コードより先に design.md を直す。

| 値 | 値 |
| --- | --- |
| 制限時間 | 60秒（仮の初期値） |
| 受付待ちの秒数（結果に入ってから開始の指示を受け付けない時間） | 1.0秒（仮の初期値） |
| 警告を出す距離（定位置からの水平距離） | 0.5m（仮の初期値）。この距離以上で警告を出す |
| 警告を消す距離（定位置からの水平距離） | 0.4m（仮の初期値）。この距離未満で警告を消す |
| 撃墜1回の加点 | +1（固定） |
| 刺され1回の減点 | -1。ただし 0 点より下にしない（固定） |

## Boundary Context
- **In scope**: ラウンドの状態（待機・プレイ・結果）と遷移の条件、残り時間、撃墜数とスコアの規則、定位置の記録と消去、離脱判定（警告を出す・続ける・消す）、状態と値の読み出し、設定値と経過秒数の検査
- **Out of scope**: トリガー入力の取得（spray-input-adapter）、撃墜・刺されたことの判定（mosquito-core）、頭の位置の取得（round-flow-adapter / game-scene）、案内・残り時間・スコア・赤い縁・離脱警告・結果の表示（round-hud-adapter）、離脱警告中にラウンドを止めること、スコアの保存とランキング、難易度の選択、設定値を保持・調整する仕組み
- **Adjacent expectations**:
  - 呼び出し側（round-flow-adapter）は、トリガーが引かれたことを開始の指示として、そのときのプレイヤーの位置とともに渡す。噴射そのものはこの spec と関係なく続く
  - 呼び出し側は、mosquito-core が出した撃墜・刺されたことを1件ずつこの spec に知らせる。この spec は mosquito-core を直接参照しない
  - 呼び出し側は、ラウンドがプレイに変わったこと・結果に変わったことを読み取り、蚊の出現の開始・停止など他の spec への指示に使う
  - 刺されたときの赤い縁は、スコアの変化ではなく刺されたことの知らせをもとに出す必要がある（0 点で刺されるとスコアは変わらないため）

## Requirements

### Requirement 1: ラウンドの開始
**Objective:** プレイヤーとして、案内が出ているときにトリガーを引いたらラウンドが始まってほしい。準備ができてから自分のタイミングで遊び始められるようにするためである。

#### Acceptance Criteria
1. The Round Core shall 最初は待機の状態にあり、残り時間を制限時間、撃墜数とスコアを 0 とする
2. When 待機の状態で開始の指示を受けたとき, the Round Core shall 時間が進められるのを待たずにプレイの状態に変え、残り時間を制限時間に、撃墜数とスコアを 0 にする
3. When 待機の状態で開始の指示を受けたとき, the Round Core shall 指示とともに渡されたプレイヤーの位置を定位置として記録する
4. While プレイの状態のとき, the Round Core shall 開始の指示を受けても状態・残り時間・撃墜数・スコア・定位置を変えない

### Requirement 2: 制限時間とラウンドの終了
**Objective:** プレイヤーとして、ラウンドは制限時間が来たら必ず終わってほしい。1回の遊びが1分で閉じるようにするためである。

#### Acceptance Criteria
1. When プレイの状態で時間が進められたとき, the Round Core shall 残り時間を経過秒数だけ減らす
2. When プレイの状態で時間が進められ、残り時間が 0 以下になったとき, the Round Core shall 残り時間を 0 にして結果の状態に変え、残り時間を超えた分の秒数は受付待ちの秒数に数えない
3. When 残り時間とちょうど同じ経過秒数で時間が進められたとき, the Round Core shall 結果の状態に変える
4. When プレイから結果の状態に変わったとき, the Round Core shall その時間経過でラウンドが終わったことを呼び出し側が読み取れるようにする
5. When プレイから結果の状態に変わったとき, the Round Core shall 撃墜数とスコアをその時点の値のまま保ち、定位置の記録を消す
6. When 経過秒数 0 で時間が進められたとき, the Round Core shall 状態も値も変えない
7. While 待機または結果の状態のとき, the Round Core shall 時間が進められても残り時間・撃墜数・スコアを変えない

### Requirement 3: 結果から待機へ
**Objective:** プレイヤーとして、結果を確かめてからトリガーを引いて次の遊びに戻りたい。制限時間の瞬間に噴射していても、結果を見逃さないようにするためである。

#### Acceptance Criteria
1. When 結果の状態に入ってから時間が進められた秒数の合計が受付待ちの秒数以上になったあとで開始の指示を受けたとき, the Round Core shall 待機の状態に変える
2. If 結果の状態に入ってから時間が進められた秒数の合計が受付待ちの秒数未満のときに開始の指示を受けたとき, the Round Core shall 結果の状態のままにし、撃墜数とスコアを変えない
3. When 結果から待機の状態に変わったとき, the Round Core shall 残り時間を制限時間に、撃墜数とスコアを 0 に戻す
4. When 結果から待機に変わったとき, the Round Core shall その同じ開始の指示ではプレイを始めず、次の開始の指示を待つ
5. When 結果から待機に変わった直後に開始の指示を受けたとき, the Round Core shall 時間が進められていなくてもプレイを始める

### Requirement 4: 撃墜数とスコア
**Objective:** プレイヤーとして、撃墜すれば点が増え、刺されれば点が減ってほしい。撃墜を狙うか顔に近づけさせないかの判断が、スコアに表れるようにするためである。

#### Acceptance Criteria
1. When プレイの状態で撃墜が知らされたとき, the Round Core shall 撃墜数を 1 増やし、スコアを 1 増やす
2. When プレイの状態で刺されたことが知らされ、スコアが 1 以上のとき, the Round Core shall スコアを 1 減らす
3. If プレイの状態で刺されたことが知らされ、スコアが 0 のとき, the Round Core shall スコアを 0 のままにする
4. The Round Core shall 刺されたことの知らせで撃墜数を変えない
5. While 待機または結果の状態のとき, the Round Core shall 撃墜と刺されたことの知らせを受けても撃墜数とスコアを変えない
6. When 複数の撃墜と刺されたことが続けて知らされたとき, the Round Core shall 知らされた順に1件ずつ反映する

### Requirement 5: 離脱判定
**Objective:** プレイヤーとして、定位置から一歩以上離れたら戻るよう警告され、戻れば警告が消えてほしい。歩き回って部屋の家具にぶつからないようにするためである。

#### Acceptance Criteria
1. When 警告していないときにプレイヤーの位置が渡され、定位置からの水平距離が警告を出す距離以上のとき, the Round Core shall 離脱警告を出すべきと答える
2. When 警告していないときにプレイヤーの位置が渡され、定位置からの水平距離が警告を出す距離未満のとき, the Round Core shall 離脱警告を出さないと答える
3. When 警告しているときにプレイヤーの位置が渡され、定位置からの水平距離が警告を消す距離以上のとき, the Round Core shall 離脱警告を続けるべきと答える
4. When 警告しているときにプレイヤーの位置が渡され、定位置からの水平距離が警告を消す距離未満のとき, the Round Core shall 離脱警告を消すべきと答える
5. The Round Core shall 定位置とプレイヤーの位置の高さの差を、離脱判定に使わない
6. If 定位置が記録されていないとき, the Round Core shall 位置にかかわらず離脱警告を出さないと答える
7. When ラウンドが始まったとき, the Round Core shall 警告していない状態から離脱判定を始める
8. The Round Core shall 離脱警告を出しているかどうかで、ラウンドの状態・残り時間・撃墜数・スコアを変えない

### Requirement 6: 状態の読み出し
**Objective:** 開発者として、ラウンドの状態と値をいつでも読み出したい。表示と他の spec への指示を、ラウンドの規則を知らずに行えるようにするためである。

#### Acceptance Criteria
1. The Round Core shall 現在の状態（待機・プレイ・結果）、残り時間、撃墜数、スコアを呼び出し側が読み取れるようにする
2. The Round Core shall 定位置が記録されているかどうかと、記録されている定位置を呼び出し側が読み取れるようにする
3. When 開始の指示を受けたとき, the Round Core shall その指示で状態が変わったかどうかと、変わった先の状態を呼び出し側が読み取れるようにする

### Requirement 7: 不正な値の拒否
**Objective:** 開発者として、壊れた設定値や経過秒数は受け付けないようにしたい。設定の入れ間違いやバグに、「ラウンドが終わらない」「警告が出ない」という症状ではなくその場で気づけるようにするためである。

#### Acceptance Criteria
1. If 制限時間、警告を出す距離、警告を消す距離のいずれかが 0 以下のとき, the Round Core shall 設定を受け付けず、どの値が不正かを呼び出し側に知らせる
2. If 受付待ちの秒数が 0 より小さいとき, the Round Core shall 設定を受け付けず、受付待ちの秒数が不正であることを呼び出し側に知らせる
3. If 警告を消す距離が警告を出す距離より大きいとき, the Round Core shall 設定を受け付けず、離脱判定の距離が不正であることを呼び出し側に知らせる
4. If 時間を進めるときの経過秒数が 0 より小さいとき, the Round Core shall 状態も値も変えず、経過秒数が不正であることを呼び出し側に知らせる

### Requirement 8: テストで確かめられること
**Objective:** 開発者として、ラウンドの規則をゲームやシミュレータを起動せずに確かめたい。見た目から推測せず、テストの結果で規則が正しいと判断できるようにするためである。

#### Acceptance Criteria
1. The Round Core shall ゲームのシーンや実行環境を起動しない自動テストだけで、Requirement 1〜7 のすべての規則を確かめられるようにする
2. The Round Core shall 外部に公開するすべての操作について、少なくとも1つの自動テストを持つ
3. The Round Core shall 残り時間ちょうど 0・受付待ちちょうど・警告を出す距離ちょうど・警告を消す距離ちょうど・0 点で刺されることの5つについて、期待する結果を自動テストで固定する
4. The Round Core shall 仮の初期値とは異なる値の組み合わせでも、規則が成り立つことを自動テストで確かめる
